Client, Server และการโต้ตอบClient, Server & Interaction

ทุกเกม Roblox มีสองฝั่ง: Server ที่เป็นเจ้าของความจริง และ Client บนเครื่องผู้เล่นแต่ละคน วันนี้เราจะรู้ว่าโค้ดควรอยู่ฝั่งไหน แล้วสร้างสิ่งที่ผู้เล่นคลิกและกด E ได้Every Roblox game has two sides: the server that owns the truth, and a client on each player's device. Today you learn which side code belongs on, then build things players can click and press E on.

1.1Server กับ Client: ใครเห็นอะไรServer vs client: who sees what

Server คือคอมพิวเตอร์ของ Roblox ที่รันเกมจริง สิ่งที่ Script เปลี่ยนจะถูกส่งต่อ (replicate) ไปให้ทุกคน ส่วน Client คือเครื่องของผู้เล่นแต่ละคน สิ่งที่ LocalScript เปลี่ยนจะเห็นแค่บนเครื่องนั้น กดปุ่มแล้วดูว่าข้อมูลวิ่งไปที่ไหนบ้างThe server is Roblox's computer running the real game; whatever a Script changes is sent (replicated) to everyone. A client is each player's device; whatever a LocalScript changes stays on that device. Press the buttons and watch where the data travels.

1.3ClickDetector และ ProximityPromptClickDetector and ProximityPrompt

สองวิธีให้ผู้เล่นโต้ตอบกับ Part: ClickDetector คลิกเมาส์หรือแตะจอ (Event MouseClick) และ ProximityPrompt ป้าย "กด E" ที่ขึ้นเมื่อเดินเข้าใกล้ (Event Triggered) ทั้งคู่ส่ง player มาให้เลย คลิกบนพื้นเพื่อเดิน แล้วลองปรับระยะและเวลากดค้างTwo ways for players to interact with a part: a ClickDetector for mouse clicks or taps (the MouseClick event) and a ProximityPrompt, the "press E" sign that appears when you walk close (the Triggered event). Both hand you the player. Click the ground to walk, then tune the range and hold time.

1.4LocalScript และปุ่มบนจอLocalScripts and on-screen buttons

UI บนจอเป็นของผู้เล่นแต่ละคน โค้ดที่ฟังการกดปุ่มจึงต้องเป็น LocalScript ที่อยู่ใน ScreenGui ใต้ StarterGui Event ของปุ่มคือ Activated (ใช้ได้ทั้งเมาส์ ทัชสกรีน และจอยเกม) ลองกดปุ่มของผู้เล่นแต่ละคนOn-screen UI belongs to each player, so code that listens to buttons must be a LocalScript inside a ScreenGui under StarterGui. A button's event is Activated (it works for mouse, touch and gamepad). Press each player's button.

2.1Debounce: กันเงินเบิ้ลDebounce: stop double pay

Touched ยิงทุกครั้งที่ "ชิ้นส่วน" ของร่างกายแตะ เท้าซ้าย เท้าขวา ขา ลำตัว... เดินผ่านเหรียญเดียวจึงอาจได้เงิน 5–10 ครั้ง Debounce คือตัวแปรที่จำว่า "เก็บไปแล้ว" แล้วไม่ทำซ้ำ ลองทั้งสองแบบแล้วดูเส้นเวลาของ EventTouched fires for every body part that touches: left foot, right foot, legs, torso… so walking over one coin can pay 5–10 times. Debounce is a variable that remembers "already collected" and refuses to repeat. Try both and watch the event timeline.

2.2CollectionService: ติด Tag แล้วสคริปต์หาเจอเองCollectionService: tag it and the script finds it

Ep1 เราใช้ Folder รวมลาวา แต่ของในเกมจริงกระจายอยู่หลายที่ Tag คือป้ายชื่อที่แปะบน Instance ได้ (แผง Properties › Tags) CollectionService:GetTagged("Coin") หาของทุกชิ้นที่ติด Tag นี้ไม่ว่าจะอยู่ที่ไหน และ GetInstanceAddedSignal แจ้งเตือนเมื่อมีชิ้นใหม่เกิดขึ้น ไม่ต้องรันใหม่In Ep1 we grouped lava in a folder, but real game objects are scattered everywhere. A tag is a label you stick on an instance (Properties › Tags). CollectionService:GetTagged("Coin") finds every tagged object wherever it lives, and GetInstanceAddedSignal tells you when a new one appears, no re-run needed.

Spawner คือ loop ที่ Clone() แม่แบบจาก ServerStorage ไปวางที่ตำแหน่งสุ่มในพื้นที่ แต่ต้องมีเพดาน MaxCoins ไม่อย่างนั้นแผนที่จะเต็มจนเกมกระตุก ปรับค่าแล้วดูว่าเงินที่ผู้เล่นได้ต่อนาทีเปลี่ยนยังไง ตัวเลขนี้จะสำคัญมากในวันที่ 4A spawner is a loop that Clone()s a template from ServerStorage to a random spot in an area. 2.4ModuleScript: ตัวเลขทั้งเกมอยู่ที่เดียวModuleScripts: every number in one place

ถ้าค่าเหรียญ 10 ถูกพิมพ์ซ้ำในหลายสคริปต์ แก้ที่หนึ่งแล้วลืมอีกที่ เกมจะพังแบบหาไม่เจอ ModuleScript เก็บตาราง Config ไว้ที่เดียว แล้วทุกสคริปต์ require() ไปใช้ ลองแก้ค่าในทั้งสองแบบแล้วเทียบกันIf a coin value of 10 is typed into several scripts, you change one and forget another, and the game breaks in ways that are hard to find. A ModuleScript keeps one Config table and every script require()s it. Edit values in both setups and compare.

3.1RemoteEvent: จดหมายข้ามฝั่งRemoteEvents: letters between sides

RemoteEvent เหมือนตู้ไปรษณีย์ใน ReplicatedStorage ที่ทั้งสองฝั่งเห็น Client ส่งด้วย FireServer(...) Server รับด้วย OnServerEvent (ได้ player เป็นค่าแรกเสมอ) แล้วตอบกลับด้วย FireClient(player, ...) กดซื้อแล้วดูโค้ดทั้งสองฝั่งทำงานสลับกันA RemoteEvent is like a mailbox in ReplicatedStorage that both sides can see. The client sends with FireServer(...), the server receives with OnServerEvent (always getting player first), and replies with FireClient(player, ...). Press Buy and watch both scripts take turns.

4.1DataStore: ความจำข้ามเซิร์ฟเวอร์DataStores: memory beyond the server

leaderstats อยู่ในหน่วยความจำของ Server พอผู้เล่นออกก็หายไป DataStore คือฐานข้อมูลบนคลาวด์ของ Roblox: GetAsync(key) โหลด SetAsync(key, data) เซฟ แต่การคุยกับคลาวด์อาจล้มเหลวได้ จึงต้องห่อด้วย pcall เสมอ ลองเล่นเหตุการณ์ต่าง ๆ แล้วเปิด/ปิดระบบเซฟและความผิดพลาดleaderstats live in the server's memory and vanish when the player leaves. A DataStore is Roblox's cloud database: GetAsync(key) loads and SetAsync(key, data) saves. Talking to the cloud can fail, so always wrap it in pcall. Play through events and switch saving and failures on and off.

4.2สมดุลเศรษฐกิจBalancing the economy

ถ้าราคาคงที่ ผู้เล่นซื้อจนหมดในไม่กี่นาที ถ้าราคาโตเร็วไป ผู้เล่นรอนานจนเลิก สูตรมาตรฐานคือ price = Price × Growth ^ level เส้นสีบอกว่าต้องเก็บเงินกี่นาทีถึงจะซื้อเลเวลถัดไปได้ เป้าหมาย: ช่วงแรกไม่เกิน 1 นาที ช่วงกลางไม่เกิน 10 นาทีWith flat prices, players buy everything in minutes; with prices rising too fast, they wait so long they quit. The standard formula is price = Price × Growth ^ level. The line shows how many minutes of collecting each next level costs. Aim for under 1 minute early on and under 10 minutes mid-game.
